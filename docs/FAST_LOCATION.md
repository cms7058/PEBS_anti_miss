# 主动定位反馈与采样质量（2026-10-26）

## 行为与边界

iOS和小程序点击后立即提交定位请求，前5秒每400毫秒读取进度。5秒未完成时只切换为“继续跟进”的进度提示，不结束请求；页面保持打开时每2秒读取同一次请求，取得新位置后自动更新地图、时间及精度。暂时断网会继续尝试读取，退出页面则停止跟进。只有服务端确认完成、真正过期或不可继续读取时结束；本地最长跟进180秒，不永久轮询。

**5秒是第一次进度反馈点，不是结束点，也不是任意网络和GPS环境下的新位置保证。** 不会重新发起同一请求，不会拿旧位置冒充新结果；后台请求仍采用原有180秒有效期。这段结果读取发生在管理端，老人手机没有增加定时请求轮询。

## 减少实际延迟

- 后端新增独立推送线程，新命令入队立即唤醒，不再等15秒的异常监测周期，APNs I/O也不阻塞老人端命令。定位命令优先于设置命令；队列重试的1秒扫描发生在服务器，不是老人手机轮询。
- iOS仅读取被查询老人，不额外等待全部家人、健康检查或通知状态；两管理端均在等待期内加快结果读取。
- 老人端0.1.13修正网络定位过早结束GPS采集的问题：GPS可用时，网络结果即使自报误差小于100米也先等待最多10秒的GPS改善窗口；收到误差100米内的新GPS样本立即上传。窗口结束后可使用本次最佳网络样本，主动查询允许粗略回退，自动围栏/到达的精度条件不放宽。GPS未启用时不额外延迟可用的精确网络估算。没有新样本仍沿用有界采集超时，不伪造位置或采集时间。室内及首次卫星定位可能超过5秒。
- 原有GPS与系统NETWORK_PROVIDER并行请求保留，首页增加“网络辅助”状态卡，读取该系统通道是否存在且已启用；不能据此承诺运营商必然返回位置。系统网络定位支持时可利用基站与Wi-Fi，具体依赖手机服务和设置，见[Android官方说明](https://developer.android.google.cn/reference/android/location/LocationManager#NETWORK_PROVIDER)。

推送CID离线、系统限制后台联网时，新命令仍可能无法到达。手机端应解除本应用电池限制，在启动管理中关闭本应用的自动管理，手动允许自启动、关联启动和后台活动，返回应用重连后再复测。允许移动数据不等于已允许后台运行；解除限制也不构成系统绝不回收的保证。

若系统提供“休眠时始终保持网络连接”，还需单独检查此开关；应用的电池白名单不能证明系统待机联网已开启。部分机型入口为“设置 → 电池 → 更多电池设置”，可参考[厂商息屏断网排查说明](https://consumer.huawei.com/cn/support/content/zh-cn00413178/)。请在真实拔掉 USB/充电器、保持锁屏的条件下连续复测。维持网络连接与持续采集 GPS 是不同操作，仍按现有围栏/行程或家属请求触发定位。

## 定位点不变的排查

新采集时间不意味着经纬度一定变化：静止、系统网络定位重复估算均可能返回相同坐标。0.1.13上传`provider`，后端以可选字段保存；iOS与小程序显示“GPS卫星定位”或“网络辅助定位（估算位置）”。旧数据标为来源未上报，不猜测来源。诊断脚本只打印来源、误差和采集年龄，不输出坐标和凭证。

更新需要覆盖安装老人端、重建后端；查看来源说明还需重新编译iOS、上传小程序体验版。旧后端仍能接收新APK的位置，但会丢弃来源字段。不要卸载老人端以免丢失绑定。

实机验收：在确认老人手机实际位置、视野开阔且允许卫星定位的情况下发起查询，核对来源、采集时间、经纬度和地图点；移动一段距离后再次核对。当前代码检查与构建不能证明目标手机实际偏差已消失；尚未取得本次实机样本。
