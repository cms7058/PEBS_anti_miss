# 划掉老人端任务后的守护（0.1.12）

## 改动

- 显式声明位置前台服务不随任务移除停止。`onTaskRemoved`和服务被回收时，在本人此前开启共享、已绑定、允许精确/后台定位且解除电池限制的条件下，安排一次恢复。重复的任务移除/销毁回调合并，10分钟窗口最多3次，避免反复崩溃造成无限重启。正常按需待命不定时定位、不安排30秒命令轮询。本人关闭共享、解绑会取消恢复，回调也重新核查同意状态。
- 已开启的前台服务新增备用SSE连接，直接从本人绑定的后台接收`sync_commands`提示。收到提示后再用设备令牌获取当前命令，避免依赖个推单一路径。正常维持一条连接，服务端60秒心跳不触发读取命令、GPS或CPU唤醒锁；断线退避5/15/30/60/120秒重连，网络切换会唤醒重连。它有少量连接流量与耗电，不能称为零耗电。
- SSE初次连接会同步一次命令，以补上断线期间的请求。停用共享时连接关闭；解绑、更换令牌会使旧连接失效。推送和SSE同时到达时沿用现有请求ID去重，不重置正在进行的同一定位采集。
- iOS和小程序的主位置卡片直接显示纬度、经度和WGS-84坐标系，可选择复制，不再只藏在详情。仍保留采集时间、精度，不用地图展示坐标转换后的值冒充原始上报坐标。
- 管理端手机设置和只读诊断工具可读取最近上报的备用连接、服务运行、后台定位和电池豁免状态；均为带时间的观察值，不是当前在线保证。

## 部署与限制

先更新后端，再安装老人端0.1.12，更新iOS和小程序以显示常驻坐标及备用通道状态。HTTP测试地址保持原值，域名未修改。后端更新按`FAST_LOCATION.md`原命令构建部署；安装包为`build/releases/familyguard-elder-0.1.12-debug.apk`，覆盖安装保留绑定。旧后端没有`/device/events`时，客户端回退到已有个推路径；需在后端更新后重新打开老人端启用新连接。

当前部署按原架构使用单个Gunicorn worker、8个线程。备用连接每个老人最多一条，新连接替换旧连接，最多同时4个老人，保留其他线程处理API；超出时返回503，客户端退避重连，仍可使用个推。需要扩大规模时应将长连接服务独立部署，不通过无限增加线程掩盖容量限制。令牌只放Authorization头，事件无令牌、身份和位置数据。

恢复闹钟不保证严格5秒执行，系统可能延迟。手机的厂商启动管理还需允许自启动、关联启动及后台活动。系统强行停止、权限被撤销、关机、无网络等不能靠本补丁绕过。Android并不保证划掉任务后所有厂商都保留进程；如果系统既不调用回调也禁止后台启动，仍需手动重新打开。

## 验收

1. 覆盖安装并打开一次，开启守护，确认后台定位、电池限制状态为已允许/已解除，允许通知；系统启动管理允许后台活动。
2. 在管理端确认能查到新位置，然后从老人手机最近任务中划掉App，锁屏2–5分钟。不要在系统设置点“强行停止”。
3. 不重新打开老人端，从管理端请求位置。核对采集时间新于本次请求，主卡片显示纬度、经度、精度；同时核对服务器命令已被读取。
4. 在老人端主动停止共享后重复测试，确认不自动复活，不返回新的位置。服务被系统直接杀死的情况需结合实际手机行为复测，不能只以构建成功代替验收。

自动验证包含：无个推发送器时SSE提示到达、设备读取命令及上传完成；真实HTTP逐帧交付与解绑撤销；WSGI提前关闭释放资源；连接替换、身份隔离、容量上限；恢复同意/权限与重试预算；原有定位、围栏、设置与管理端回归。以上自动验证不代替实机验收；锁屏实测见下节，划掉任务后的稳定性仍待验收。

## 2026-10-23 锁屏实机排查

已通过 USB 调试连接 Hi nova 11（Android API 31），校验安装的 0.1.12 APK 与本地发布文件一致。以下时间为北京时间：

| 测试条件 | 请求时间 | 结果 |
| --- | --- | --- |
| 移动数据、锁屏、USB 接线供电 | 19:20 | 约2秒内取得新位置 |
| 临时模拟未充电及深度休眠，USB 仍连接 | 19:21、19:23 | 两次均取得本次新采样 |
| 真正拔掉 USB、不充电、保持锁屏 | 19:49、19:54 | 两次请求均到期，未记录到手机读取命令 |
| 仅重新接线，保持锁屏且未打开老人 App | 20:02 | 约2秒内取得新位置 |

接线检查时守护前台服务、原进程均存在，后台定位和电池白名单有效，没有本应用的系统禁网规则。重新接线开放调试后核对到主进程 PID、服务启动次数均未变化，没有新增退出记录。因此这次故障不属于服务退出后依靠打开 App 重启；物理拔线会改变结果，模拟休眠通过不足以证明脱离电脑后可用。

随后用户确认系统“休眠时始终保持网络连接”处于关闭状态，并手动开启。该设置独立于本应用的电池豁免，不能根据电池白名单推断它已经开启；部分系统提供的对应入口见[厂商说明](https://consumer.huawei.com/cn/support/content/zh-cn00413178/)。仅开启此设置并重新启用守护后，备用连接曾登记，但锁屏约一分多钟后登记消失，20:18 的新请求仍未及时被读取，不能认定此设置单独解决了问题。

进一步核对发现老人端在厂商“应用启动管理”中仍处于自动管理。本人关闭自动管理并手动允许自启动、关联启动及后台活动，重新启用守护后确认已拔线锁屏，并反馈管理端可以正常返回定位。这支持厂商自动后台管理是本次故障的重要因素；此前已确认的 Android 电池白名单与该厂商管理不是同一项。此结果属于用户实测反馈，更改后的两轮持续锁屏查询及更长时间稳定性验收尚未完成。

测试结束已解除强制休眠、恢复真实电池状态并还原临时应用日志开关。调试命令没有更改手机后台权限；休眠联网和启动管理选项由本人操作。没有增加待机定位或命令轮询。

同时复现并修正管理端的一处重试问题：本地等待结束早于服务端请求到期时，页面会保留旧的 pending 快照。再次点击原先仅查询这条旧请求，需要再点一次才能发新请求。iOS 和小程序现在每次手动点击都提交到已有定位请求接口，由服务端返回仍有效的同一请求或替换已过期请求；同一有效请求不会重复入队。自动跟进和页面恢复仍沿用原请求。管理端重试修复与手机后台系统设置是两项独立处理，不能以管理端构建通过代替手机长期稳定性验收。
