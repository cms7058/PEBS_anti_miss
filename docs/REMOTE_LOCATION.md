# 按需定位与省电守护（2026-10-22）

## 使用和升级

必须先更新云端后端，再覆盖安装老人端 0.1.2，最后用 Xcode 重新运行管理端；小程序需重新编译或上传体验版。

服务器在仓库目录执行：

```sh
git pull --ff-only
sudo env HTTP_BIND_IP=0.0.0.0 docker compose -f deploy/compose.http.yaml up -d --build --wait
curl --fail http://127.0.0.1:8087/health
```

数据库启动时自动增加独立的定位请求表，保留原有账号、绑定、位置及规则，不要删除数据卷。

老人端 APK：`android/app/build/outputs/apk/debug/app-debug.apk`。覆盖安装后打开，确认已开启守护、定位和后台运行权限。若旧版本未开启守护，需首次点击开始；之后不应要求每次查询都点击。

管理端进入某位老人的详情，点击“获取最新位置”；“立即刷新后台数据”只读取服务器已收到的数据。页面自动刷新后显示等待接收、已接收、完成或超时。

## 实现范围

- 此版用约30秒一次的短 HTTP 请求检查指令，没有接入厂商推送，也没有持续保持业务长连接。网络请求不等于每次启动 GPS。检查间隔在一次网络请求完成后计算。
- 普通模式默认约5分钟定位一次；围栏或 active 行程时约1分钟一次。位置未更新阈值较短时，普通模式自动缩短为阈值的一半（最短60秒）。
- 每次定位订阅网络和 GPS，取得精度100米以内的新位置后立即停止本次订阅；45秒内未取得精确位置时使用本次较优的粗略位置，完全没有位置则停止并等待重试。粗略位置仍不用于越界和到达判断。
- 定时采集频率受指令检查周期、网络耗时和系统调度影响；后台休眠可能显著延迟。没有持有持续唤醒锁，也没有绕过系统强制停止限制。
- 请求有效期180秒，同一老人的待处理请求合并。请求完成后距离创建不足30秒时暂不接受新请求。
- 后端只把带匹配 request_id、采集时间不早于请求时间且通过原有位置校验的上报标记完成。普通定时上报和旧缓存不代表远程请求成功。
- 解除绑定时清除待处理请求。已授权查看的家属可以请求新位置，未授权账号和其他设备不能访问该老人的指令。
- 这版保留了自动守护。降低采样频率会增加围栏提醒延迟；网络中断、定位不准或系统休眠也会影响连续越界判断。

## 接口

- POST `/elders/{id}/location-request`：创建或返回当前待处理请求。
- GET `/device/commands`：当前设备读取自己的待处理请求和最新设置，状态转为 received；没有指令时 location_request 为 null。
- POST `/device/location`：可增加 request_id；新旧版本的普通上报仍兼容。
- 管理端快照增加可空的 location_request，字段 id、requested_at、expires、state、completed_at。每位老人只保留最新请求。

## 真机验收

1. 先确认后台更新成功，再覆盖安装 APK、重新编译 iOS，账户和绑定应保留。
2. 老人端开始守护后返回桌面，管理端请求一次位置；检查请求完成且采集时间在请求之后。
3. 锁屏重复测试，记录响应时间；断网测试应超时，不能把旧位置显示成本次成功。
4. 无围栏时观察上报间隔，再开启围栏或行程观察间隔缩短。
5. 连续使用数小时对比耗电；此版本尚未进行真实老人手机耗电或长时间锁屏验收。
6. 停止守护后不应再采集新位置；重新开始后恢复。强制停止或重启后的限制与之前相同，需重新打开应用。
